# VESC FOC для К1946ВК035

[![Лицензия прошивки: GPLv3](https://img.shields.io/badge/license-GPL--3.0-brightgreen)](LICENSE)

Открытый проект: неофициальный порт алгоритмов бессенсорного векторного управления [VESC](https://github.com/vedderb/bldc) на отечественный К1946ВК035 / К1921ВК035 (Cortex-M4F).

Автор порта и адаптации прошивки — **Regulo**. Автор и разработчик используемой платы — **TDMLab**: [К1946ВК035 BLDC BOARD](https://github.com/TDMLab/K1946VK035_BLDC_BOARD). Алгоритмы VESC разработаны Benjamin Vedder и участниками проекта; наблюдатель MXLEMMING происходит из MESC, автор — David Molony.

В проекте ведётся адаптация FOC и периферии под отечественный МК. Это экспериментальная прошивка, а не готовый сертифицированный регулятор. Исходники прошивки опубликованы для изучения и доработки на условиях GPLv3 с сохранением уведомлений исходных компонентов. [Веб-конфигуратор FOC](https://regulo.ru/foc-configurator/) — отдельный проект, его исходники в этот репозиторий не входят. Для связи с платой используется USB–UART.

## ⚙️ Возможности

| Параметр | Текущая реализация |
|---|---|
| Микроконтроллер | К1946ВК035, Cortex-M4F, ядро 100 МГц |
| ШИМ | 25 кГц, счёт вверх-вниз, dead-time 40 тактов / 0,4 мкс на соответствующем фронте |
| Обычный контур FOC | **6,25 кГц**, шаг 160 мкс |
| Измерения | Три фазных тока и напряжение питания, запуск АЦП от SOCA PWM0 |
| Управление | Бессенсорный запуск, ток, скорость, open-loop и удержание вектора |
| Определение параметров | R, L и потокосцепление; R/L проверены на стенде |
| Обмен | UART1, 115200 бод, 8N1, PB8/PB9, разъём CN3 |
| Настройки | Блок 128 байт, версия формата и CRC16, страница Flash с адреса `0xF000` |

При включении питания токовые нули калибруются на закрытых ключах. В STOP выходы находятся в Hi-Z. Снятие программной аварии не включает выходы — для работы нужна отдельная команда запуска.

Частота несущей ШИМ и частота расчёта FOC различаются. Сейчас обычное управление работает на **6,25 кГц**. Работа над повышением частоты контура до **25 кГц** продолжается, но в текущей версии ещё не завершена. Для измерения L выполняется отдельная короткая серия из четырёх выборок АЦП через 40 мкс, без выполнения обычного FOC. После импульса восстанавливаются усреднение АЦП и период 160 мкс.

## 📥 Установка и сборка

### npm / xpm

Нужны Git и Node.js **20 или новее** с npm. Доступ в интернет необходим для загрузки инструментов. В Windows проверены Node.js 24.18.0 и npm 11.16.0.

```sh
git clone https://github.com/RRegulo/K1946VK035_VESC.git
cd K1946VK035_VESC
npm install
npm run configure
npm run build
```

`npm install` запускает `postinstall`: xpm устанавливает ARM GCC 14.2.1, CMake 3.31.9 и Ninja 1.13.1, отдельный скрипт устанавливает [OpenOCD с поддержкой К1921ВК035](https://github.com/DCVostok/openocd-k1921vk/releases). Архив OpenOCD проверяется по SHA-256. Отсутствующая в архиве конфигурация цели К1921ВК035 копируется из `.vscode/k1921vk035.cfg`; этот файл входит в репозиторий. Автоматическая установка OpenOCD предусмотрена для Windows x64 и Linux x64; на других платформах инструменты нужно устанавливать вручную.

| Команда | Назначение |
|---|---|
| `npm run` | Список доступных команд |
| `npm run configure` | Настройка Release в `build` |
| `npm run build` | Сборка Release |
| `npm run configure:debug` | Настройка Debug в `build-debug` |
| `npm run build:debug` | Сборка Debug |
| `npm test` | Тесты алгоритмов, параметров и протокола на ПК |

Для `npm test` дополнительно нужен **нативный GCC или Clang в PATH**. ARM-компилятор из xpm его не заменяет. Тесты используют программные модели периферии и не проверяют силовую часть.

Результаты сборки: `build/K1946VK035_BLDC_BOARD.{elf,hex,bin}`; для Debug — аналогичные файлы в `build-debug`.

**Состояние зависимостей инструментов.** При проверке 1 ноября 2026 года `npm install`, настройка, обе сборки и тесты выполняются. `npm audit` сообщает о 35 уязвимостях, включая 2 critical, во встроенных зависимостях xpm 0.23.3. Совместимый `npm audit fix` их не устраняет; `--force` не применяется, поскольку предлагаемый откат xpm ломает выбранную схему установки. Эти Node.js-пакеты работают на ПК и не включаются в прошивку МК. Для сборки без xpm можно использовать ручную установку инструментов или Dev Container.

### Ручная сборка

Установите ARM GCC, CMake и Ninja и добавьте их в PATH:

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

cmake -S . -B build-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug

cmake --build build --target host_tests
```

### Dev Container

Установите Docker, VS Code и Dev Containers. Откройте проект и выполните **Dev Containers: Reopen in Container**. Конфигурация устанавливает ARM GCC, нативный GCC, CMake, Ninja и OpenOCD. Затем:

```sh
cmake --build build
cmake --build build --target host_tests
```

Подключение `/dev` в этой конфигурации рассчитано на Linux-хост. На Windows проброс USB-отладчика в контейнер требует отдельной настройки. Полный цикл npm и отладка проверены на Windows; запуск контейнера в этой проверке не выполнялся.

## 🔌 Прошивка и отладка

Используются SWD и OpenOCD с поддержкой К1921ВК035. Для VS Code установите [Cortex-Debug](https://marketplace.visualstudio.com/items?itemName=marus25.cortex-debug) и выберите конфигурацию DAPLink в `.vscode/launch.json` под нужную сборку. Подключение J-Link также предусмотрено в конфигурации.

Для проверенного DAPLink используется **CMSIS-DAP v2 / `usb_bulk`**; настройка находится в `.vscode/daplink-swd.cfg`. На другом отладчике может потребоваться другой бэкенд. Перед подключением сверяйте SWDIO, SWCLK, GND, опорное напряжение и питание по документации платы и отладчика.

### Светодиоды

| Светодиод | Вывод | Значение |
|---|---|---|
| LED1 | PA14 | Мигает с частотой 1 Гц при нормальной работе прошивки, в том числе в STOP. При аварии гаснет. |
| LED2 | PA15 | При аварии мигает с частотой 5 Гц. В нормальном состоянии выключен. |

LED1 показывает, что работает программа, а не что двигатель обязательно вращается. Вывод PA14 используется для индикации статуса.

## 🎛️ Первое подключение мотора

Откройте [FOC configurator](https://regulo.ru/foc-configurator/), подключите плату через USB–UART (UART1, 115200 бод, 8N1), нажмите **«Подключить (UART)»** и выберите порт USB–UART. Проверьте показания питания. До измерений задайте число пар полюсов и подходящие лимиты. Мотор должен быть закреплён, пропеллер снят.

Последовательность на вкладке **«Измерение»**:

1. **«Измерить R»** → дождаться успеха → **«→ параметры»** в строке R.
2. **«Измерить L»** → дождаться успеха → **«→ параметры»** в строке L.
3. **«Измерить λ (мотор вращается)»** → дождаться успеха → **«→ параметры (и KV)»**.
4. В STOP на вкладке **«Параметры»** → **«Сохранить во flash»**.
5. На вкладке **«Управление»** → небольшое задание в **«Обороты, об/мин (мех.)»** → **«Задать»**. Остановка — **STOP**.

R отображается в мОм, L — в мкГн, λ — в мкВб. Перенос результата сначала меняет RAM, запись во Flash выполняется отдельной кнопкой. При измерении λ вал вращается; не запускайте эту процедуру с установленным пропеллером или незакреплённым мотором. Ошибочные результаты не применяйте.

## 🐛 Ограничения и защиты

- Прошивка экспериментальная, адаптация и испытания продолжаются.
- В обычном режиме включены программные OV/UV. Пороги берутся из параметров; начальные значения — 8–25 В. SW_OC и ADC_SAT в обычном режиме отключены. Короткая серия L отдельно прерывается при насыщении АЦП или превышении ограничения тока импульса.
- PWM TZ/HD по умолчанию отключены. `-DENABLE_EXPERIMENTAL_PROTECTION=ON` разрешает непроверенную аппаратную конфигурацию; цифровые компараторы АЦП для полноценной защиты по току не настроены.
- Программные OV/UV можно снять `CLEAR_FAULT` в STOP при допустимых измерениях. Аппаратные трипы требуют перезапуска. Сброс аварии не включает мост.
- Нет CAN/DroneCAN, DShot, осциллографа с захватом буфера и сброса аппаратных защёлок по UART. Соответствующие неподдерживаемые команды возвращают NAK.
- Поля CAN и `adc_trig` сохраняются ради совместимости блока настроек, но здесь не применяются. Kp/Ki рассчитываются по R/L и `cc_tc_us`; `OBS_V_RAW` применяется к напряжению наблюдателя.
- Значения R/L зависят от мотора, измерительной цепи, питания и настройки импульса. Стендовая проверка процедуры не является калибровкой точности.

Для первого включения закрепите мотор, уберите пропеллер и используйте источник с ограничением тока. Программные проверки не заменяют аппаратную защиту моста.
